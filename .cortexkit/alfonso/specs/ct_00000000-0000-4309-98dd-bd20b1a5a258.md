  - `Ok(empty)` for a `git_common_dir` failure, which stays "no remotes";
  - `Err(OS error text)` for an I/O error reading `config`, including invalid UTF-8.
- `ownership::root_remotes` (`ownership.rs:60-67`) returns `rusqlite::Result<(Vec<GitRemote>, Option<String>)>`. The `rusqlite::Error` stays for SQL failures only. The `Option` is the git-config error text: `None` when the config was read or there was no git dir, `Some` when the read failed. On `Some` the vec is empty and `effective_owned_names` isn't applied to a fabricated list. A git error never propagates through `?`, so it never aborts the enable plan or a `resolve_remote` query.
- Every consumer handles the git error explicitly:
  - The reply that serves a root's remotes is empty and carries one additive field. Its Rust name is `remotes_error`, its wire key follows that struct's existing serde rename, and its value is the OS error text. It is `Option<String>` with `skip_serializing_if = "Option::is_none"`, so it is absent otherwise and byte-level goldens don't change.
  - Register and add-root (`root_keys::incoming`, `root_keys.rs:42`) still succeed. On the error they don't call `choose`, so no remote key and no label key is minted. An existing key is left unchanged.
  - The enable-state backfill (`enable_state.rs:249-265`) rebuilds `project_root_key` from `choose` for every root, and continues past a root with the error. For that root it skips `choose` and carries the root's current key instead. The per-root association lives on `project_root.root_key`/`root_key_kind`, and the key row is `project_root_key(project_id, kind, root_key, created_at)` (`log_schema.rs:53-66`). If the root has a key, the backfill reads that row and passes it through unchanged, keeping its original `created_at` rather than `now`. It pushes the row (deduplicated like chosen rows), pushes the root's `RootKeyMapping`, and inserts the key into the same `owners` map. If another project holds that key, the plan returns `root_key_exists` and publishes nothing. A root with no key carries nothing. The backfill mints no key and drops no carried row.
  - `resolve_remote` (`ownership.rs:136-166`) treats a root with the error as matching nothing and still considers every other root. Resolution doesn't name the error; the root's remotes reply does, through `remotes_error`.
  - `set_owned_remotes` (`ownership.rs:204`): on `Err` it refuses with `remotes_unreadable` and the OS error text, appends no journal entry and writes no override. `Ok(empty)` keeps today's behaviour. `replay_ownership_op` doesn't read git config and is unchanged.
  - A readable config with zero GitHub remotes keeps today's label fallback and omits the field.
- The unreadable-config test is an integration test in `crates/entorhinal-core/tests/`. It denies read with mode 000 on Unix, and with the shared deny-read ACL helper on Windows (see Tests and fixtures).
- Comments, other sections, conditional includes and URL rewrites are skipped, not errors. The README says conditional includes and URL rewrites are unsupported.
- On Windows, a test that can't create a `.git` symlink (missing privilege) skips at runtime and prints its name and the reason.
- The incarnation marker accepts exactly one trailing `\n` or `\r\n` (`read_token`, `binding.rs:231-243`). Anything else stays malformed.
- After the incarnation marker is created, the containing directory is fsynced on Unix before the binding commits. On Windows the existing `file.sync_all` is the strongest step available, and a comment next to it says so.

### Retry output (F23)
- In `execute_agents`, `approval is pending on this Mac` (`cli.rs:1044`) becomes exactly `approval is waiting at the operator prompt`. The confirmation gate doesn't change (see non_goals F22).
- The agents retry line is quoted for the platform the CLI runs on. Other callers of `shell_word` stay POSIX.
  - POSIX keeps today's `shell_word` (`cli.rs:970`) and the prefix `retry: ck agents ` (`cli.rs:1037`). A word is left bare if it is non-empty and every byte is ASCII alphanumeric or in `_./:-`. Otherwise it is wrapped in single quotes, with `'` written as `'\''`.
  - PowerShell always wraps in single quotes, with `'` written as `''`, and the line starts `retry (pwsh): ck agents `. The supported shell is PowerShell 7.3 or later (`pwsh`, standard native argument passing). Windows PowerShell 5.1 isn't supported.
- Both quoting functions and the retry-line renderer live in `crates/entorhinal-module/src/retry_quote.rs`, which uses only `std`. entorhinal-module has only a bin target (`crates/entorhinal-module/Cargo.toml:11-13`), so `cli.rs` declares it as a module, and the integration test `crates/entorhinal-module/tests/retry_quote.rs` includes the same file with `#[path = "../src/retry_quote.rs"]`.
- Unit-test both functions on every OS with these exact vectors:

  | Input | POSIX | PowerShell |
  |---|---|---|
  | `a b` | `'a b'` | `'a b'` |
  | `a'b` | `'a'\''b'` | `'a''b'` |
  | `a"b` | `'a"b'` | `'a"b'` |

- The execution test in `crates/entorhinal-module/tests/retry_quote.rs` renders the retry arguments with the included renderer and runs them into `ckdev-argv-echo`, through `sh -c` on Unix and `pwsh -NoProfile -Command` on Windows. It asserts that spaces, both quote characters and the request key arrive unchanged.
  - `ckdev-argv-echo` is a new `[[bin]]` of entorhinal-module with `test = false`. It prints its argv as JSON, and the test locates it through `CARGO_BIN_EXE_ckdev-argv-echo`.
- The retry keeps the original request key, including one that contains a space and a quote.

### Tests and fixtures (F26, F27, F28, F29, F30)
- Shared fixtures that register roots use `RegistryStore::canonical_mutation_root`. That includes `Fixture::dir` (`mutations.rs:2287-2294`), which today uses `canonicalize` plus `to_string_lossy`. One deliberate test keeps showing that a non-canonical (verbatim) path is refused with `not_canonical`.
- Golden comparisons are of two kinds:
  - Goldens that may parse JSON replace the path value before serializing, or compare parsed JSON.
  - Byte-level wire goldens (`disabled_journal_golden.rs`, and any golden whose comment forbids re-encoding) never parse and re-encode. They register the production canonical string and substitute its JSON string encoding (`serde_json::to_string` of that string) in the raw bytes, whatever prefixes and separators it contains. Backslash doubling is never hand-rolled.
- The CLI path test (`cli.rs`, the symlink canonicalization test near 2059) compares the CLI's output with `RegistryStore::canonical_mutation_root`.
- `ck_domain.rs` drops its crate-level `cfg(unix)` gate (`ck_domain.rs:14`).

## intent
The operator ruled that every CortexKit module supports macOS, Linux and Windows. A report-only census of entorhinal (36 findings, F01-F36) found it builds and passes its whole suite on Linux, and cross-compiles for Windows, but several operator paths fail or silently degrade off macOS. Some findings are shared hazards on macOS too.

This campaign fixes the findings that live in entorhinal's own code and dependency pins, and adds native macOS and Windows CI so the result stays fenced. Findings owned by the subc daemon or its libraries are handed to their owner and are not in scope (see non_goals).

End state:
- `ck projects`, `ck workspaces` and `ck agents` find a running daemon wherever the daemon publishes its connection file, on all three systems.
- On Windows, every CLI mutation sends a path in exactly the form core compares, so register, add-root, attach and workspace set-root work.
- The module never guesses its store location. A missing storage descriptor is a startup refusal, so no test or misconfigured launch can open the live registry by accident.
- Store, lease and log files are owner-only on Windows, as they already are on Unix.
- Path guards (the home-ancestor guard, liveness containment, the volume boundary) compare native path components, not `/`-joined strings.
- Git metadata edge cases (a `.git` symlink, a separate git dir, an unreadable config, a CRLF marker) are handled or refused by name instead of silently losing remotes.
- CI runs clippy and the full test suite natively on Linux, macOS and Windows.
