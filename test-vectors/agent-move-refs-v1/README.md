# Served move session references v1

These records come from `agent.move_refs` through the real module handler,
using the two-machine move acceptance fixture. They are synthetic data, not
captured user sessions. The reader is `reserved:occipital`, an ordinary
participant principal.

| File | Meaning |
|---|---|
| `source.json` | Source checkpoint reply after admission and publication. |
| `receiver.json` | Receiver checkpoint reply after pickup, before importing any sessions. |
| `unknown-cut.json` | Receiver refusal for a cut with no local checkpoint (`unknown_move`). |

The source and receiver replies are identical: `{cutId, agentId, refs}` inside
the module's `result` envelope. The refs are the frozen plan's distinct session
refs, sorted by `(ref_kind, ref)`, not the current bindings on either machine.
Two participants share the `session` kind, so duplicate routed refs appear only
once. A whole-agent participant receives the synthetic `agent` ref during the
move, but that ref is absent from these replies. Entorhinal's synthetic
`package-closure` and `session-bindings` kinds are also excluded by the handler
and covered by its unit tests.

The source bindings end after admission; the receiver has no bindings yet.
Both still return the same three refs. Only the randomly generated cut ID is
normalized, to `aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`; successful handler reply
bytes are otherwise preserved verbatim. The unknown cut is
`bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb`.

## Reproduce and verify

From the repository root, generate only these files:

```sh
ENTO_WRITE_SERVED_VECTORS=1 cargo test --workspace --all-targets --locked -- move_refs_records_match_published_files
```

Run without the environment variable to compare the real handler's bytes and
SHA-256 checksums against the published files. The test is also the drift guard
for this sample set; changing the handler does not silently update the samples.

```sh
cargo test --workspace --all-targets --locked -- move_refs
(cd test-vectors/agent-move-refs-v1 && shasum -a 256 -c SHA256SUMS)
```

`SHA256SUMS` lists all three JSON files. Earlier sample directories are not
regenerated by this command.
