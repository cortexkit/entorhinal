# Catalog consumer v1 served samples

Generated by `served_vectors::catalog_consumer_v1_requests_match_published_files`
through the real `catalog_consumer::check` and `catalog_consumer::prefetch`
functions. A fake discovery service declares one skill consumer and one flow
consumer, and each fake log route captures the actual `(method, args)` call.
Package hashes, publisher fingerprints, plan ID, and generation ID use fixed,
obviously fake values. The flow is a directly constructed `PreparedPackage`;
installing flows is not required to pin the request shape.

- `check.json`: the exact `catalog_consumer.check` params captured for each
  declared capability, plus the accepted check reply and a refusal reply. Each
  consumer's `packages` array contains only its declared kind.
- `prefetch.json`: the exact `catalog_consumer.prefetch` params captured for
  each declared capability and its accepted `{"ready":true}` reply. Each
  consumer's `packages` array contains only its declared kind.

In both files, `requests` records the fake consumer module, its declared
capability, the method passed to the route, and the params passed with it. The
reply fields are the method result objects, before the transport's outer
`result` envelope. The test compares these files byte for byte unless the write
environment variable is set.

Regenerate from the repository root:

```
ENTO_WRITE_SERVED_VECTORS=1 cargo test --workspace --all-targets --locked served_vectors::catalog_consumer_v1_requests_match_published_files
```

`SHA256SUMS` records the checksums of these two JSON files and this README;
recompute it after regeneration so consumers can verify their copies.
